# UC5 — Inventory Catalog, Stock Adjustments & Material Reservations

## 1. Catalog, Inventory & Valuation Policies

UC5 governs master data for units and materials, physical stock additions and corrections, and queued-job material requirements and reservations.

### Roles & Access Boundaries
- **Admin**: Creates/edits units and materials; adds physical stock with unit costs; performs physical count corrections with mandatory audit reasons; reads financial valuation and unit costs.
- **Worker**: Reads material catalog (with costs redacted); creates, edits, and rechecks material plans for queued jobs; reserves available stock. Workers cannot perform stock additions or edit catalog master data.
- **Customers & Suppliers**: Have no access to inventory or stock endpoints.

### Catalog & Base Units
- Each material has one immutable base unit. Base unit conversion factors are not used. To change units, a new material record is created.
- Names are case-insensitively unique. Materials can be marked inactive (`is_active = false`), which prevents new reservations while allowing existing reservations to be released.

### Stock Valuations & Adjustments (NUMERIC 18,6)
- **Stock Additions (`mode = addition`)**: Requires a positive quantity and a non-negative `unit_cost`. Recalculates weighted-average unit cost:
  $$\text{New Avg} = \frac{(\text{Current On-Hand} \times \text{Current Avg}) + (\text{Added Qty} \times \text{Unit Cost})}{\text{Current On-Hand} + \text{Added Qty}}$$
  Rounded half-up to 6 decimal places.
- **Count Corrections (`mode = correction`)**: Sets the absolute counted on-hand balance. Current average cost is retained (even when corrected to zero). Corrections cannot reduce physical on-hand below active reservations.

## 2. Queued-Job Material Plans & Reservations

Workers plan raw materials for queued jobs:
- **Available Stock Calculation**:
  $$\text{Available} = \text{On-Hand} - \sum \text{Active Reservations across all jobs}$$
- **Job Allocation**:
  $$\text{New Job Reservation} = \min(\text{Required}, \text{Previous Job Reservation} + \text{Available})$$
  $$\text{Shortage} = \text{Required} - \text{New Job Reservation}$$
- **Non-Consumption Invariant**: Reserving or releasing materials **never alters physical on-hand quantity or average cost**. Physical stock is only consumed when production actuals are recorded in UC8.
- **Lifecycle Guard**: Plan edits and reserve top-ups are permitted **only while the job is in `queued` status**. Once production starts (UC8), material requirements and reservations are frozen against UC5 edits.

## 3. API Endpoints

| Method | Path | Permission | Description |
|---|---|---|---|
| `POST` | `/units` | Admin | Create measurement unit (e.g. `kg`, `pcs`) |
| `GET` | `/units` | Staff | List units (up to 1,000) |
| `POST` | `/materials` | Admin | Create raw material record |
| `PATCH` | `/materials/{id}` | Admin | Edit material name or active state |
| `GET` | `/materials` | Staff | Search material catalog (average cost redacted for Workers) |
| `POST` | `/materials/{id}/stock` | Admin | Record stock addition or physical count correction |
| `GET` | `/materials/{id}/movements` | Staff | Audit ledger of stock movements (costs redacted for Workers) |
| `PUT` | `/jobs/{job_id}/materials` | Worker | Replace planned material requirements and allocate available stock |
| `POST` | `/jobs/{job_id}/materials/reserve` | Worker | Top up allocations for saved plan after new stock arrives |
| `GET` | `/jobs/{job_id}/materials` | Staff | Inspect current job material plan, reservations, and shortages |

## 4. Concurrency & Integrity Architecture

- **Row Lock Ordering**: Plan transactions lock the request, then the job, and then all affected material rows in ascending UUID order to guarantee deadlock-free concurrent execution.
- **PostgreSQL Triggers**: Database triggers maintain `qty_reserved` aggregates on the `material` table and reject any update that would over-reserve or cause negative stock.
- **Audit Trails**: All movements write immutable records to `stock_movement` and catalog changes write to `material_catalog_audit`.
