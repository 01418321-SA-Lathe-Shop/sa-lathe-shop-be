# UC1 — Customer Registration, Company Joining & Request Submission

## 1. Business Scope & Rules

UC1 handles customer self-registration, invitation-based company membership, manufacturing request submissions, private file attachments in S3, and transactional event notifications.

### Customer & Company Accounts
- **Registration (`POST /auth/register`)**: Customers self-register as either `individual` or `company`.
- **Company Ownership**: Registering a new company requires `company_name`; the creator becomes the company owner. Company names are descriptive and do not automatically merge duplicate entries.
- **Company Invitations**: Company owners issue invitations via `POST /customers/{customer_id}/invitations`. Invitation tokens are shown once, expire in 24 hours, and can be redeemed once. Only SHA-256 digests are stored.
- **Joining an Existing Company**: A user joins via `POST /customers/join` with `{"invitation":"<token>"}` or registers with an invitation token instead of a company name.
- **Addresses**: Public registration of a new individual or company customer requires `address` (1–500 characters, newlines allowed). It becomes the customer's first address and also fills the billing address. Registration with an invitation must omit it; the company's addresses apply. Members read addresses with `GET /customers/{customer_id}/addresses`; only the owner adds more with `POST /customers/{customer_id}/addresses` and `{"address":"..."}`. Addresses cannot be edited or removed yet (to be defined). Migration 000018 copies existing non-empty billing addresses.
- **Shared Access**: All active members of a company share read access to that company's requests and can act on quotations and submissions.

## 2. API Endpoints

| Method | Path | Permission | Description |
|---|---|---|---|
| `POST` | `/auth/register` | Public (rate limited) | Register individual or company customer |
| `GET` | `/customers` | Customer | List customer profiles/companies the user belongs to |
| `POST` | `/customers/{customer_id}/invitations` | Company Owner | Generate a one-use 24-hour invitation token |
| `GET` | `/customers/{customer_id}/addresses` | Customer Member | List the customer's addresses |
| `POST` | `/customers/{customer_id}/addresses` | Customer Owner | Add another address |
| `POST` | `/customers/join` | Customer | Join a company using an invitation token |
| `POST` | `/requests` | Customer Member | Submit a manufacturing job request |
| `GET` | `/requests` | Customer Member / Staff | List requests (scoped to company for customers; all for staff) |
| `GET` | `/requests/{request_id}` | Customer Member / Staff | Read request details |
| `POST` | `/requests/{request_id}/uploads` | Customer Member | Request private upload intent for drawing/spec |
| `POST` | `/uploads/{attachment_id}/complete` | Original Uploader | Verify content and freeze file into final S3 storage |
| `GET` | `/requests/{request_id}/attachments` | Customer Member / Staff | List ready attachments for a request |
| `GET` | `/attachments/{attachment_id}/download` | Customer Member / Staff | Generate short-lived signed download link (10 min) |
| `GET` | `/notifications` | Authenticated User | Read personal inbox notifications |
| `PATCH` | `/notifications/{notification_id}/read` | Notification Owner | Mark inbox notification as read |

### Request Submission Payload
```json
{
  "customer_id": "00000000-0000-4000-8000-000000000001",
  "description": "Rubber compression mould insert",
  "qty": 2,
  "material_spec": "S45C Carbon Steel",
  "deadline": "2026-12-01T10:00:00+07:00"
}
```
- `customer_id`: Required UUID; user must have active membership.
- `description`: 1–10,000 Unicode characters.
- `qty`: Positive `int64` quantity (no artificial business maximum).
- `material_spec`: Optional, up to 2,000 characters.
- `deadline`: Optional RFC 3339 timestamp (must be in the future; indicates requested deadline, not promised completion).

## 3. Private File Upload Lifecycle

To prevent exposure of customer intellectual property, all drawings and attachments are stored privately in S3:
1. **Upload Intent**: Customer calls `POST /requests/{id}/uploads` with `file_name`, `content_type`, and `byte_size`.
   - Allowlist: PDF, DOC/DOCX, XLS/XLSX, TXT, JPEG/PNG.
   - Size limit: Max 100,000,000 bytes (100 MB).
   - API returns a pre-signed S3 PUT URL and required headers (valid for 10 minutes).
2. **Direct PUT**: Client uploads file bytes directly to SeaweedFS/S3.
3. **Completion & Inspection**: Customer calls `POST /uploads/{attachment_id}/complete`.
   - The backend validates file signatures, magic bytes, dimensions (images), and OLE/OOXML structures (rejecting embedded macros/VBA).
   - Validated staging objects are copied to a final private S3 key using an ETag precondition.
   - The database stores only object keys and metadata—never raw file bytes or permanent public URLs.
4. **Authorized Downloads**: Downloads generate short-lived signed URLs (10 min expiry) after checking current company membership or staff roles.

## 4. Transactional Outbox & Notification Delivery

- **Transactional Outbox**: New requests insert outbox events in the same database transaction as the request.
- **Worker Dispatch**: The background worker claims outbox rows using `FOR UPDATE SKIP LOCKED` with 60-second leases.
- **Inbox**: Dispatches notifications to the submitting customer and all active Admin/Worker inboxes. `(event_id, account_id)` prevents duplicate deliveries.
- **LINE Integration**: Sends alerts only to the single configured Admin user ID (`LINE_ADMIN_USER_ID`) using `X-Line-Retry-Key` for idempotency. Disabled by default during tests.
