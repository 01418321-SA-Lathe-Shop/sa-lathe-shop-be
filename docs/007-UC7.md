# UC7 — Material Receiving, Replacement Claims & Supplier Settlement

## 1. Operational Policies & Financial Boundaries

UC7 implements goods receiving from suppliers, damage inspection, replacement claim tracking, credit term management, and supplier payment settlement. Owner confirmations were finalized on 2026-10-19.

### Key Policies
1. **Role Separation**:
   - Both **Admin and Worker** can view operational order lines, receive physical shipments, and log external replacement claims.
   - **Admin Only**: Supplier prices, unit costs, credit terms, payment settlement, and payment evidence uploads/downloads are strictly restricted to Admin. Worker views automatically redact all financial fields.
2. **Order Eligibility & Deliveries**:
   - Receiving is permitted only for accepted, non-cancelled orders.
   - Partial deliveries are supported. Unexpected excess beyond the ordered quantity is strictly rejected.
   - Once any receipt (even an all-damaged delivery) is recorded, the order is permanently locked against cancellation.
3. **Physical Stock & Costing Valuation**:
   - Only **good quantities** enter usable stock and contribute to the weighted-average cost.
   - Damaged items **never enter usable stock** and remain outstanding until replaced by good units.
4. **Replacement-Only Claims**:
   - Claims are strictly replacement-only. No refunds, credit notes, or write-offs are supported.
   - An order reaches full receipt (`received`) only when all ordered quantities have arrived as good stock (including good replacement shipments).
5. **Credit Terms & Settlement**:
   - Admin sets `credit_days` explicitly once per order (counted from `full_received_at`). No default credit period exists.
   - **Single Settlement**: One full payment for the entire order total, executed only after 100% good receipt. Installments are not supported.
   - Payment method: `bank` (requires private proof upload) or `cash` (proof optional).

## 2. API Endpoints

| Method | Path | Permission | Description |
|---|---|---|---|
| `GET` | `/receiving/orders` | Admin / Worker | List accepted orders needing receiving (costs redacted for Workers) |
| `GET` | `/receiving/orders/{order_id}` | Admin / Worker | Detailed receiving state (costs redacted for Workers) |
| `POST` | `/receiving/orders/{order_id}/receipts` | Admin / Worker | Record physical receipt of original or replacement goods |
| `POST` | `/receiving/orders/{order_id}/claims/{claim_id}/submit` | Admin / Worker | Log external contact/claim with supplier regarding damaged goods |
| `POST` | `/receiving/orders/{order_id}/credit-terms` | Admin | Set credit days for the order |
| `POST` | `/receiving/orders/{order_id}/settlement` | Admin | Record full cash or bank payment settlement |
| `POST` | `/material-orders/{order_id}/evidence/uploads` | Admin | Initiate signed private upload for payment proof |
| `POST` | `/order-evidence/{evidence_id}/complete` | Admin Uploader | Complete and freeze payment proof in S3 |
| `GET` | `/order-evidence/{evidence_id}/download` | Admin | Download signed private payment proof |

## 3. Database Schema & Migration 000010

- `material_receipt`: Records receipt timestamp, receiving actor, and notes.
- `material_receipt_item`: Lines recording good vs damaged quantities linked to stock movements.
- `material_claim`: Tracks damaged defect quantities, external contact notes, and resolution via replacement items.
- `order_evidence`: Stores S3 keys and metadata for private supplier payment slips.
- `material_order`: Extended with `full_received_at`, `credit_days`, and `payment_status` (`unpaid`, `pending`, `paid`).
