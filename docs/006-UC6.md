# UC6 — Supplier Management & Procurement Orders

## 1. Procurement Policies & Confirmed Decisions

UC6 implements raw material purchasing from external suppliers. Owner decisions were confirmed on 2026-10-18.

### Key Policies
1. **Admin-Only Procurement**: Only active Admins can create suppliers, place purchase orders, record supplier responses, cancel orders, or view procurement history. Workers have no access to procurement routes.
2. **External Suppliers**: Suppliers do not have system accounts. Admin records external communications (phone, LINE, email).
3. **Flexible Job References (Option A)**:
   - Each order has one supplier, 1–100 material lines, and 0–100 flexible job references.
   - Orders can consolidate shortages from multiple jobs, exceed shortages, or replenish general shop stock.
   - Job references are informational links and do not create rigid per-job allocations or lock UC5 material plans.
4. **Order Immutability**: Placed quantities, prices, supplier details, and job links cannot be edited. To alter an unreceived order, cancel it and place a new order.
5. **Supplier Rejection**: Admin records supplier rejection with a mandatory reason, which cancels the entire unreceived order.
6. **No Inventory Effect**: Placing, accepting, rejecting, or cancelling supplier orders **never alters physical on-hand stock, reservations, or average costs**. Stock increases only occur upon physical receipt in UC7.
7. **Pricing Arithmetic**:
   $$\text{Line Total} = \text{round}_{\text{half-up}}(\text{quantity} \times \text{unit\_cost}, 2)$$
   $$\text{Order Total} = \sum \text{Line Totals}$$
   Quantities and unit costs use `NUMERIC(18,6)`; line and order totals use `NUMERIC(18,2)` THB without VAT.

## 2. API Endpoints

All endpoints require Bearer authentication with an active **Admin** session.

| Method | Path | Permission | Description |
|---|---|---|---|
| `POST` | `/suppliers` | Admin | Create supplier master record |
| `GET` | `/suppliers` | Admin | Search suppliers by substring name |
| `PUT` | `/suppliers/{supplier_id}` | Admin | Replace supplier contact and active details (versioned) |
| `POST` | `/material-orders` | Admin | Place immutable material order |
| `GET` | `/material-orders` | Admin | List material orders (filterable by referenced `job_id`) |
| `GET` | `/material-orders/{order_id}` | Admin | Detailed view including snapshots, lines, links, and events |
| `POST` | `/material-orders/{order_id}/actions` | Admin | Record external supplier accept/reject or shop cancellation |

### Example Payloads

**1. Place Material Order (`POST /material-orders`)**:
```json
{
  "idempotency_key": "8b08c365-0696-42e1-b3ed-7daf52f8c906",
  "supplier_id": "a97da349-cbd6-48fc-8bba-e2692d42b0d5",
  "job_ids": ["da0b5482-824c-4bc4-aa65-bb7c587e9bbd"],
  "expected_at": "2026-11-01T09:00:00+07:00",
  "lines": [
    {
      "material_id": "2f13e6bd-a07e-49c7-b8ea-c48a7c9f920b",
      "quantity": "25.000000",
      "unit_cost": "0.335000"
    }
  ]
}
```

**2. Record Supplier Action (`POST /material-orders/{id}/actions`)**:
```json
{
  "idempotency_key": "4b812864-0f3c-482b-bdc2-e10ac9ffce84",
  "expected_version": 1,
  "action": "reject",
  "reason": "Supplier cannot deliver specified billet dimensions"
}
```

## 3. Order Lifecycle & Retry Contract

| Current Status | Action | Resulting Status & Version |
|---|---|---|
| New | `place` | `ordered` / `pending`, version 1 |
| `ordered` / `pending` | `accept` | `ordered` / `accepted`, version +1 |
| `ordered` / `pending` | `reject` (+ reason) | `cancelled` / `rejected`, version +1 |
| `ordered` / `accepted` | `cancel` (+ reason) | `cancelled` / `accepted`, version +1 |

- **Replay Contract**: Sending an identical request with the same `idempotency_key` returns the original result snapshot from `material_order_event`. A changed payload with an existing key returns HTTP 409 Conflict.
- **Intentional New Orders**: Re-ordering the same materials requires a new idempotency key.

## 4. Database Schema & Migration 000009

- `supplier`: Stores supplier name, email, phone, and `is_active`.
- `supplier_audit`: Immutable audit log of supplier changes.
- `material_order`: Stores `order_no`, `supplier_id`, total amount, status, supplier snapshots, and expected delivery date.
- `material_order_item`: Stores line items, frozen material/unit snapshots, quantities, unit costs, and rounded line totals.
- `material_order_job`: Association table linking orders to referenced jobs.
- `material_order_event`: Append-only event history storing canonical commands and original results.

## 6. Use-Case Description Alignment (2026-11-03)

Source: `Use_Case_Description_UC1-UC12.md`. Conflicts are listed in `025-uc-spec-alignment.md`.

Matches the description: one supplier per order (the description split by supplier is covered by creating one order per supplier); placed quantities and prices are immutable; expected date; a supplier rejection cancels the unreceived order with a reason; suppliers have no accounts.

Conflicts kept at the confirmed rule:
- Actor: the description has a Technician place orders (UC6 Actor). Procurement is Admin only (`006-UC6.md` section 1). The description is not followed.
- Payment status on the order at creation (`unpaid`, Q6.3). Supplier payment is recorded at settlement in UC7, not on the order.

Described but not implemented as written:
- Alternative supplier search after a rejection (Q6.E2). Admin creates a new order with another supplier instead.
- A shortage-to-order summary (Q6.1) that subtracts reserved and on-order quantities. Verify whether the current plan and shortage views expose this figure before relying on it.
