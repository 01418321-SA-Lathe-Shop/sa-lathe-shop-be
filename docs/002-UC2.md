# UC2 — Estimation & Quotations

## 1. Confirmed Pricing Rules

Pricing rules were confirmed by the shop owner on 2026-10-15:
- **Total Cost Markup**: Minimum quotation price = `(material_cost + labor_cost) * 1.60` (60% markup on total estimated costs).
- **Whole-Request Totals**: Quoted costs and prices represent the **total for the entire requested quantity**, not unit prices.
- **Rounding**: Minimum price rounds **upward to the nearest satang** (0.01 THB).
  - *Example 1*: Material 800.00 + Labor 200.00 = 1000.00 total cost → Minimum price is 1600.00.
  - *Example 2*: Material 0.01 + Labor 0.01 = 0.02 → $0.02 \times 1.60 = 0.032$ → Minimum price rounds up to **0.04**, not 0.03.
- **Final Price Bound**: Worker may set a `final_price` greater than or equal to the calculated minimum, but never below it.
- **No VAT**: THB amounts have two decimal places; no VAT or tax fields exist.
- **Data Representation**: Amounts are represented as exact JSON decimal strings (e.g. `"1600.00"`) and stored as `NUMERIC(18,2)` in PostgreSQL.

## 2. API Endpoints

All endpoints require Bearer authentication. Only active **Workers** can estimate, create drafts, edit drafts, send quotations, or refuse requests. Admins have read-only access to staff quotation details.

| Method | Path | Permission | Description |
|---|---|---|---|
| `POST` | `/quotations/estimate` | Worker | Calculate cost total and rounded minimum price preview |
| `POST` | `/requests/{request_id}/quotations` | Worker | Create a draft quotation (or new revision) |
| `PATCH` | `/quotations/{quotation_id}` | Worker | Edit draft quotation with expected lock version |
| `POST` | `/quotations/{quotation_id}/send` | Worker | Publish immutable quotation snapshot to the customer |
| `GET` | `/quotations/{quotation_id}` | Worker / Customer Member | Read quotation (costs redacted for customers) |
| `GET` | `/requests/{request_id}/quotations` | Worker / Customer Member | List quotation revision history |
| `POST` | `/requests/{request_id}/reject` | Worker | Worker refuses a pending request with a reason |
| `GET` | `/requests/{request_id}/rejection` | Worker / Customer Member | Read request refusal reason |

### Example Payloads

**1. Price Preview (`POST /quotations/estimate`)**:
```json
{"material_cost":"800.00","labor_cost":"200.00"}
```

**2. Create Draft (`POST /requests/{request_id}/quotations`)**:
```json
{
  "material_cost": "800.00",
  "labor_cost": "200.00",
  "final_price": "1600.00"
}
```

**3. Send Quotation (`POST /quotations/{quotation_id}/send`)**:
```json
{"expected_lock_version": 1}
```

**4. Worker Refusal (`POST /requests/{request_id}/reject`)**:
```json
{"reason": "Cannot machine this geometry with shop lathe tolerances"}
```

## 3. Access Boundaries & Lifecycle Transitions

### Internal Cost Redaction
- **Staff View**: Workers and Admins see `material_cost`, `labor_cost`, `total_cost`, `minimum_price`, and `final_price`.
- **Customer View**: Customers see **only `final_price`** and version/status metadata. Internal material and labor costs and calculated minimums are completely omitted from customer responses, including in revision history.

### Request & Quotation States
- Creating a draft keeps the parent request in `pending` status.
- Sending a quotation sets its status to `sent`, records `sent_at`, and updates the parent request to `ongoing` within a single database transaction. Sent prices become completely immutable.
- Only one active (draft, sent, or approved) quotation can exist per request at any time.
- If a sent quotation is rejected by the customer in UC3, Worker is permitted to create a new revision linking to the predecessor with an incremented version number.
- **Worker Refusal**: A Worker can refuse only a `pending` request. This immediately sets the request status to `canceled` with an audited reason. This is distinct from customer quotation rejection in UC3.
